# 시연 운영 가이드 — 클립 카메라 고장 시

> 상황(2026-10-02): XIAO ESP32-S3 보드는 정상이나 카메라 모듈과 버튼이 고장. 실시간 신호 API는 승인 대기 중.

세 가지 방법을 목적에 따라 고릅니다. 어느 방법이든 **화면과 발표에서 무엇이 실제이고 무엇이 대체인지 먼저 밝힙니다.**

| 방법 | 보여 주는 것 | 실제 | 대체 | 준비 |
| :-- | :-- | :-- | :-- | :-- |
| **A. 노트북 카메라 라이브** (권장) | 앱 전체 흐름: 보행 안내·시간 부족·불일치·점멸 | 앱·판정 코드, 카메라 판독(실시간 영상), 통신 규약 | 카메라 센서(노트북 카메라), 신호 데이터(시연값) | 노트북만 |
| **B. 고장 보드 그대로** | 하드웨어 고장 감지 → 안전 정지 | 보드·Wi-Fi·펌웨어·앱 | 없음 | 보드 USB, 펌웨어 업로드 |
| **C. 카메라 모듈 교체** | 원래 설계 그대로 | 전부 | 신호 데이터(시연값, API 승인 전까지) | 교체 부품 |

## 방법 A — 노트북 카메라를 클립 카메라 대신 사용

노트북 카메라 영상을 펌웨어와 **같은 HTTP 통신 규약**(통신 규약 검사 24/24 통과)으로 내보내므로 앱은 보드와 구별하지 못합니다.

```bash
# 1) 노트북 카메라를 클립 카메라로 (터미널 1)
export CLIP_DEVICE_TOKEN=demo-token
python3 scripts/clip_cam_sim.py --webcam 0 --port 8790

# 2) 실제 앱 실행 (터미널 2) — 시연 신호: 초록 30초 → 빨강 20초 반복, 화면에 "시연 데이터" 표시
cd app
flutter run -d macos \
  --dart-define=CLIP_CAM_HOST=127.0.0.1:8790 --dart-define=CLIP_CAM_TOKEN=demo-token \
  --dart-define=DEMO_SIGNAL=cycle --dart-define=CLIP_DEBUG=true
```

앱 조작: 교차로 선택(GPS가 없으면 목록에서 고르기) → 방향 선택 → 화면을 한 번 눌러 안내 시작.

시연 순서(약 2분):

1. 휴대폰에 초록 보행신호등 사진을 띄워 노트북 카메라 정중앙에 비춘다 → 시연 신호가 초록이면 **"지금 건너셔도 됩니다, N초 남았습니다"**.
2. 남은 시간이 7초 아래로 내려가면 **"안전하게 건널 시간이 부족합니다"** — 카메라가 초록이어도 막는다.
3. 시연 신호가 빨강일 때 초록 사진을 계속 비추면 **"신호가 일치하지 않습니다"** — 이중 검증.
4. 손으로 렌즈를 가리면 **"카메라가 신호등을 찾지 못했습니다"** — 추측하지 않는다.

화면 없이 터미널로만 같은 흐름을 보려면 `scripts/run_demo_flow.sh --webcam 0`.

주의: 휴대폰 화면은 실제 신호등과 밝기·색이 달라 판독이 흔들릴 수 있다. 화면 밝기를 최대로, 거리 30~50cm.

## 방법 B — 고장 난 보드로 "고장 감지" 시연

펌웨어는 카메라 초기화에 실패해도 부팅·Wi-Fi 연결을 계속하고, 상태를 숨기지 않는다.

| 요청 | 카메라 고장 시 응답 |
| :-- | :-- |
| `GET /health` | `cameraOk:false`, 마지막 오류 `esp_camera_init_failed` |
| `GET /capture` | `503 capture_failed` (이전 사진을 재전송하지 않음) |
| 앱 | 카메라 확인 불가 → 대기 안내. 보행 안내는 절대 나오지 않음 |

업로드: [firmware/README.md](../../firmware/README.md). BOOT 버튼이 고장이면 USB로 바로 업로드를 시도하고, 업로드 모드 진입이 안 되면 BOOT 패드(GPIO0)를 GND에 잠깐 연결한 채 USB를 꽂는다. RESET 버튼 대신 USB를 뺐다 꽂는다.

발표 문구 예: "카메라가 고장 난 실제 보드입니다. 기기는 고장을 숨기지 않고 알리고, 앱은 안내를 멈춥니다. 틀린 초록을 말하지 않는다는 원칙이 하드웨어 고장에서도 지켜집니다."

## 방법 C — 카메라 모듈 교체

XIAO ESP32-S3 **Sense**의 카메라는 보드 위 확장 보드의 커넥터에 꽂히는 OV2640 모듈이다.

1. 먼저 카메라 리본 커넥터를 뺐다가 끝까지 다시 끼운다. 접촉 불량이 가장 흔한 원인이다.
2. 그래도 `cameraOk:false`면 OV2640(또는 호환 OV3660) 모듈 또는 Sense 확장 보드를 교체한다.
3. 교체 후 `scripts/check_clip_cam_contract.py http://보드IP`로 통신 규약 24항목을 검사한다.
