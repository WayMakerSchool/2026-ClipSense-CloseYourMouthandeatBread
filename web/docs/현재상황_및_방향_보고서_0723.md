## 1. 프로젝트 한 줄 요약

**ClipSense** — 옷깃 클립 카메라 × 경찰청 C-ITS 실시간 신호 × 비전 분석을 교차 검증해 시각장애인의 횡단보도 횡단을 음성·진동으로 보조하는 시스템. 제8회 한국코드페어 SW공모전 2차 예선 출품작 (팀 입닫빵: 임채환·이유찬).

핵심 주장 (발표의 한 문장):
> ClipSense는 두 센서가 같은 색인지 확인하는 데 그치지 않고, **같은 횡단보도·같은 방향을 보고 있는지, 정보가 아직 유효한지, 횡단 시간이 충분한지**를 검사하며, 하나라도 불확실하면 진행 가능 상태를 즉시 해제한다.

## 2. 오늘(7/23)까지 구현 완료된 것

### 2-1. v1 프로토타입 (오전 완성, main 머지)

React + Vite + PWA 웹앱. 서면 제출물의 "React+Vite+PWA로 개발 중" 서술과 일치.

- **이중 검증 판정 엔진**: C-ITS 초록 AND 비전 초록 AND 잔여시간 충분 → CROSS, 그 외 전부 WAIT (Fail-Safe: 함수의 기본값이 대기)
- Tier 1(완전검증)/2(비전단독)/3(무신호) 자동 전환 — C-ITS 장애 시 자동 강등
- HSV 기반 신호등 색 판별 (내장 카메라), 비대칭 히스테리시스 (허가는 1.5초 유지 시, 차단은 즉시)
- 한국어 TTS + 진동 패턴, 검증 현황 화면, 시나리오 원클릭 주입

### 2-2. SafeGraph-RTA 연구 계층 (오후 완성, main 머지)

v1을 A/B 실험의 **기준선(baseline)으로 보존**한 채, 그 위에 런타임 안전 계층을 추가:

- **문제 재정의**: 기존 Boolean AND는 두 초록이 ① 같은 횡단보도인지 ② 오래된 데이터인지 ③ 정지/재전송된 관측인지 확인하지 않는다 → 잘못된 대상·낡은 데이터가 우연히 초록이면 통과시킬 수 있다
- **SafeGraph-Lite 즉시검사 12종**: 대상 일치(5필드), 신선도(source/receive/vision age), 순서·재전송, 영상 정지, 이중 초록, score/quality, 시간 예산
- **비대칭 RTA 상태기계**: WAIT → CONFIRMING → SIGNAL_CONFIRMED. 승인은 서로 다른 5프레임 + 1.5초 유지 필요, 위험 입력은 **같은 판정 주기에 즉시 해제**
- **안전 불변식 P1~P7 전수 테스트**: "확정 상태 ⇒ 모든 검사 통과"를 조합 스윕 + mutation check로 증명
- **결함주입 실험**: 결정론 시나리오 11종 × 3엔진, `npm run experiment` 한 명령으로 JSONL/CSV/보고서 자동 생성 (수치 손기입 0)

### 2-3. 실측 결과 (전부 로그에서 추적 가능, 재현 가능)

| 지표 | Raw AND | AND+Stabilizer (주 기준선) | **SafeGraph-RTA** |
|---|---|---|---|
| CVER (계약위반 6종 중 통과시킨 수) | 5/6 | 5/6 | **0/6** (단측 95% 상한 39.3%) |
| UAER (물리위험 4종) | 1/4 | 1/4 | 1/4 — 공통원인 잔존위험 (아래 참고) |
| DPR (위험 tick 노출) | 483/823 | 453/823 | **85/823** |
| Safe Coverage | 85/85 | 85/85 | 85/85 (가용성 손실 없음) |
| 정상 확인 지연 | 0ms | 1500ms | 1500ms |
| 위험 전환 차단 (Time-to-Inhibit) | 0ms | 0ms | 0ms (동일 tick) |

- **H1 입증**: 잘못된 횡단보도 / 오래된 C-ITS / 패킷 재전송 / 영상 정지 — 4종 전부에서 기존 방식은 통과, SafeGraph는 완전 차단
- **정직하게 공개한 한계**: PERSISTENT_COMMON_CAUSE(두 소스가 같은 대상·정상 timestamp로 같은 거짓 초록을 지속 제공)는 SafeGraph도 통과함 → 본선 과제(독립 관측·불확실성 보정)로 명시

### 2-4. 품질 상태

- 테스트 **360/360 통과** (v1 66개 무수정 보존 + 신규 294개), 빌드·실험 3종 명령 전부 통과
- 태스크 20개 전부 구현→독립 리뷰→수정→재리뷰 게이트 통과. 리뷰가 잡아낸 결함 4건(통신두절→빨간불 오분류, 무의미 테스트, 재전송 시나리오 비지속, 시연 화면 클럭 불일치) 모두 수정·기록됨 — **"문제 발견→수정→재검증" 이력 자체가 발표 소재**

## 3. 정직성 경계 (발표·문서에서 지킬 것)

**주장 가능**: 정의된 소프트웨어 결함 시나리오에서 기준선과 비교했다 / 대상·신선도·순서·시간 불변식을 런타임 검사한다 / 불일치 시 같은 주기에 해제한다 / 로그·테스트로 재현 가능하다.

## 5. Claude AI와 논의하고 싶은 방향 (논의 안건)

### 즉시 (예선, ~7/26)
1. **4분 발표 스토리 구성** — 권장 골격: 25초 문제상황 → 35초 기존 방식의 반례 → 40초 SafeGraph 구조 → 60초 시연(정상→주입→차단) → 50초 정량 비교(CVER 5/6→0/6) → 30초 직접 구현 부분 → 20초 한계·본선 계획. 이 배분이 최적인지, "우리가 우리 1차 프로토타입의 반례를 스스로 발견하고 고쳤다"는 서사를 어디에 배치할지
2. **Q&A 예상질문 30문항** — 특히: "MOCK인데 의미 있나", "HSV가 AI인가", "실제 도로에서 되나", "공통원인 오류는 어떻게 할 건가", "수동 바인딩이면 반쪽 아닌가" 류의 공격적 질문에 대한 [직접답변→근거→한계→다음 검증] 형식 답안
3. **평가 기준 매핑 점검** — 우수성·독창성 25 / 설계·방법론 25 / 구현 완성도 25 / 발표 25에 현재 산출물이 각각 어떻게 대응되는지, 빈 곳이 있는지

### 본선 (예선 통과 시)
4. **자동 대상 연결(graph association)** — 지도·방향·영상 기반으로 수동 바인딩 제거하는 설계
5. **공통원인 오류 대응** — 독립 관측 추가, 불확실성 보정(selective prediction), risk–coverage 곡선
6. **실증 로드맵** — ESP32 클립캠 실물 연동, 실교차로 촬영 세션, 시각장애인 당사자 피드백
7. **Flutter 네이티브 포팅** — 서면에 목표 아키텍처로 명시했으므로 본선까지의 전환 계획
