# 라이브 촬영 대본 — 폰 실기기 5장면 (7/24~25)

목표: "실제로 정상 작동하나?"에 대한 답. 폰 실기기에서 앱이 돌고, 통신이 끊기면 즉시 대기로
전환되는 것을 **로그와 함께** 찍는다. 로그 없이 찍은 영상은 그냥 영상이고, 로그와 함께 찍은
영상은 검증 자료다.

기존 3막(시나리오 A/B, `demo-checklist-v2.md`)과 별개의 촬영이며, 최종 시연영상은
[라이브 5장면] + [시나리오 A/B 하이라이트]를 편집으로 합친다.

## 0. 사전 세팅 (촬영 전날 확인)

**노트북 (서버 역할)**

- [ ] `npm run dev -- --host` 실행 → 터미널에 `https://<노트북IP>:5173` 표시됨 (HTTPS 자동)
- [ ] 노트북 개인 핫스팟 켜기 (또는 폰과 같은 WiFi)
- [ ] `https://<노트북IP>:5173/cits-mock` 을 노트북 브라우저에서 열어 JSON 응답 확인

**Android 폰 (시연 기기)**

- [ ] 핫스팟/같은 WiFi 접속 → Chrome에서 `https://<노트북IP>:5173` 접속
- [ ] 인증서 경고 → "고급 → 계속" (자가서명 개발 인증서 — 정상)
- [ ] Chrome 메뉴 → **"홈 화면에 추가"** = PWA 설치 (이 장면 자체가 촬영 소재)
- [ ] 카메라 권한 허용, `🔈 오디오 활성화` 클릭 (TTS 사용자 제스처)
- [ ] `카메라 라이브` 모드 전환 → SourcePanel에 `MOCK(네트워크) · 연결됨` 배지 확인
- [ ] 상태 스트립의 `E2E p95` 숫자가 갱신되는지, `로그 다운로드 (JSONL)` 버튼 동작 확인
- [ ] **10회 연속 재실행 리허설** (§26 요구사항 — 새로고침 10번, 매번 정상 기동 확인)

**보조 모니터**: 보행 신호등 초록/빨강 이미지 또는 영상 준비 (폰 카메라로 비출 대상)

## 5장면 (Track A — 폰 단독, 약 55초)

### 장면 1 — 착용/휴대 (약 8초)
- [ ] ESP32 실물이 있으면: 옷깃에 클립 부착 컷 (Track B 성공 시 실스트리밍, 실패 시에도
      부착 컷 + "통신 셋업은 본선" 정직 자막)
- [ ] ESP32가 없으면: 폰을 가슴 포켓에 카메라가 전방을 향하게 거치 —
      자막: **"폼팩터 검증용 대체 구성 (클립 HW는 사양·설계 완료, 본선 셋업)"**
- 나레이션: "옷깃의 카메라와 주머니 속 스마트폰. 양손은 자유롭습니다."

### 장면 2 — 접속 (약 8초)
- [ ] 폰이 핫스팟으로 노트북에 접속 → PWA 아이콘으로 앱 실행되는 화면
- 나레이션: "폰은 백그라운드 연산 장치입니다. 별도 전용기기가 필요 없습니다."

### 장면 3 — 실시간 판정 (약 15초)
- [ ] 폰 카메라를 모니터의 **빨간불**에 비춤 → `대기` (빨간 배경) + 게이트 패널 BLOCK 표시
- [ ] 모니터를 **초록불**로 전환 → `확인 중`(VERIFYING) → 5프레임+1.5초 후 `신호 확인됨`
      → **TTS 발화 + 실제 진동** (Android)
- [ ] 화면 상단 `E2E p95: NNNms` 가 같은 프레임에 잡히도록 구도 잡기 — **이게 ② 숫자 실측 장면**
- 나레이션: "네트워크의 신호 데이터와 카메라 관측이 모두 확인될 때만, 5프레임과 1.5초를
  기다린 뒤 알립니다."

### 장면 4 — Fail-Safe: 비행기 모드 (약 12초) ★ 가장 비싼 증거
- [ ] `신호 확인됨` 상태에서 **비행기 모드 ON** (화면에 토글 동작이 보이게)
- [ ] 수 초 내 `대기` 전환 + 사유 `CITS_MISSING`(통신 두절) + `MOCK(네트워크) · 끊김` 배지
- [ ] 비행기 모드 OFF → 재연결 → 다시 확인 절차 처음부터 (즉시 복귀하지 않음도 보여주기)
- 나레이션: "통신이 끊기면, 마지막 초록불을 기억해서 안내하는 게 아니라 **즉시 대기**합니다.
  불확실하면 멈춘다 — 이 원칙이 코드로 존재합니다."

### 장면 5 — 로그 (약 8초)
- [ ] `로그 다운로드 (JSONL)` 클릭 → 파일 저장 → 파일 내용 몇 줄 화면에 노출
      (frame_id·양 채널 상태·판정·지연 ms가 한 줄에 찍힌 것)
- 나레이션: "방금 보신 모든 판정은 이 로그로 재검증할 수 있습니다."
- [ ] **촬영 직후 이 로그 파일을 보관** — E2E 지연 실측치·한계 기록·Q&A 수치의 원료

## Track B — ESP32 실물 (7/24 오전, 2~3시간 타임박스)

보드: XIAO ESP32-S3 Sense. 성공 조건: MJPEG 스트림 URL 확보.

1. Arduino IDE → 보드 esp32 (XIAO_ESP32S3) → 예제 `CameraWebServer` (PSRAM 활성) →
   WiFi를 노트북 핫스팟 SSID로 → 플래시
2. 시리얼 모니터에서 스트림 URL 확인 (예: `http://<esp32-ip>:81/stream`)
3. 앱 카메라 라이브 모드 → `[내장 카메라|ESP32]` 토글 → URL 입력
   (CORS 문제 시: URL 대신 `/esp32-proxy?url=http://<esp32-ip>:81/stream` 입력 — dev 전용 프록시)
4. 성공 시: 장면 1·3을 ESP32 스트림 기준으로 재촬영 + **제품컷·착용컷 사진** (⑤) +
   구동 중 발열·끊김 횟수·지속시간 기록 (④ 한계 목록)
5. **타임박스 초과 시 미련 없이 중단** — Track A 영상으로 확정, ESP32는 사진과 본선 로드맵으로
